# Vision

`sc-open-corpus` exists so that anyone building tools for solution consultants can prove, on the same real mess and the same answer keys, how much of a company's public knowledge their AI step turns into answers that are right, current and safe to send.
It serves the builder of a sales-knowledge tool and the solution consultant deciding whether to trust one, and it turns a real company's public material into a scored run.
It owns exactly one thing: a public test company for sales knowledge - the before-AI state an SC actually inherits, and the keys that score what any harness makes of it.

## Real material, honestly held

Every original is something its owner publishes, fetched byte for byte with a plain client, with its URL, date, sha256 and licence recorded.
A page that refuses automated fetching is recorded as a failure with the reason; it is never worked around with another identity, a proxy, a cache or an archive copy.
Openly licensed files are shared; everything else is held for private testing, and the public cut ships its URL, hash and a fetch script instead.
A buyer's words stay with the buyer: their questions and answers are quoted only where the licence allows, and paraphrased or linked everywhere else.
Nothing is said about a real company that its own sources do not say, except a planted fault, and every planted fault is either true to an older source or explained in the keys.
The repository holds only public material; anyone's private material runs through a local overlay that uses the same tools and protocol and is never committed, named or described here.

## Before AI is the mess people inherit

The before-AI state is never cleaned by hand.
It is laid out the way an SC receives it: a content library export with its manifest, an answer library export, a buyer's tender pack, a list of bookmarks.
Library shapes come from real tools, structure only, and every kind of mess is one seen in a real library or a real run: byte-identical copies under other names, expired items, employee-only and do-not-use-with-AI flags, an internal file that slipped in, a document about the wrong company, a scan with no text layer, an answer a release made untrue, text addressed to AI agents.
Real faults in a vendor's own material are kept as found and scored, never tidied away.

## The harness is the importer

The corpus ships no importer and no answers called the truth.
The after-AI state is whatever a run produces, published as a dated run with its model, time, cost and log, so builders can diff their own output against real runs on the same inputs.
A run is evidence of what one harness did on one day; it is never promoted to gold, and a better run replaces nothing in the keys.
Green Room is the first client, not the owner: any harness can load a delivery, and the corpus never bends to make one tool look good.
When a run exposes a tool's weakness, the finding goes to that tool; the corpus changes only if the finding shows the corpus was unfair.

## Open keys, fresh tests

Keys are independent of every tool and live outside every workspace a run can read.
The strongest key is gold by construction: a vendor's own completed questionnaire answering its own blank form, a buyer's published answer to a vendor's question.
Planted faults carry the evidence that makes them faults; fact questions carry a quote that verifies verbatim against the source text.
Keys for openly licensed material are published in full, so anyone can score their own tool without asking.
Because published keys can be tuned against, proof comes from the next delivery: each refresh brings changes and questions no tool has seen, and a score is quoted with the delivery it was earned on.
The run protocol is written before any run and changes only by a dated addition; a run that reads the keys while loading is void.

## Score what a seller would pay for

A Yes the vendor says No to is counted on its own, because one risky commitment outweighs many missing answers.
Carried faults are ranked by severity, and right facts a tool wrongly flags count against it too.
Reading is mostly solved; the scores exist to expose meaning calls - which source wins, what is stale, what must go to a person.
Every score states its cost and time, and a stronger result that costs far more is reported as a trade, not a win.
Tools and models may be compared on the same inputs; the companies whose material is held are subjects, never scored or ranked.

## Dated, refreshable, honest about gaps

Every corpus carries an as-of date, and every original its own fetch date.
Knowledge arrives in deliveries, as it does at work: a first collation, then what changed.
A refresh re-fetches from the live web and turns real changes into the next delivery; nothing is backdated or silently replaced.
What could not be fetched is listed with the reason, so a gap reads as a gap and never as absence.
For anyone who wants to test further, the repository points to where good public SC material lives - open handbooks, published questionnaires, public tenders with clarification answers - without ranking it.

## Scope

It is not a content library product, not a RAG retrieval benchmark, not a scraper, and not a leaderboard of the companies whose material it holds.
The portals are labelled test fixtures with generic names; they imitate no vendor's brand and make no statement for the companies named.
Code is MIT; fixtures and keys written for the corpus are CC BY 4.0; every original keeps its owner's terms.

A change aligns when it adds real, licensed material that an SC actually uses, mess that a real library or run has shown, a key that verifies against its source, a fresh delivery that tools have not seen, or a score that better separates safe answers from risky ones.
A change should be resisted when it cleans the before-AI state, fabricates or upgrades a company's claims, works around a refusal, lets a run read the keys while loading, promotes a run to gold, ranks the companies themselves, tunes the corpus to a tool, or brings private material into the repository.
